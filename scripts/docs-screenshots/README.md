# Documentation screenshots

The images on help pages (currently `/help/temples`, from
`src/app/help/temples/images/`) are generated by driving the real app in headless
Chromium. Nothing is captured by hand, so they can be regenerated whenever a screen
changes, and they can never contain real people.

## Rules

- **Synthetic data only.** Temple "Example", members "Synthetic Member A–D",
  Creator and Reader (the local test sign-ins), mottos such as "Fiat Pax", the join
  code `example-join-code`. Never a real temple, member, email or invitation.
  Ritual titles are fine. Add people to `fixtures.ts`, not to a screenshot step.
- **No dev furniture.** The Next dev overlay is removed before every capture. Do not
  crop in a way that shows other fixtures from the local database (for example
  `Fixture Temple`); clip to the elements you mean to show.
- **Regenerate, commit the images with the change.** If you edit a help page or a
  screen it shows, run the capture and look at every affected image.

## Running it

Needs the local development stack (PostgreSQL, MinIO, `.env.local`) and Chromium:

```sh
nvm use 24          # the repo requires Node 24
./dev               # in another terminal: the app on http://localhost:3004
pnpm docs-screenshots:seed      # idempotent; builds the Example temple
pnpm docs-screenshots:capture   # all shots; or: ... capture editor-split members
```

`DOCS_SCREENSHOTS_ORIGIN` points the capture at a different origin and `CHROMIUM`
at a different binary. The capture signs in with the dev-only test buttons
(`LOOM_LOCAL_TEST_LOGIN=1`), publishes the sample rituals once (readers only get a
ritual after its saved version is published), then writes WebP files.

## Adding a shot

1. Add a `Shot` to the list in `capture.mts`: a `name` (the file name), a `persona`
   (`creator` is a temple administrator, `reader` a grade 1 member), an optional
   `viewport`, an `open` function that gets the page into the wanted state, and
   usually a `clip` expression naming the elements to frame.
2. Run `pnpm docs-screenshots:capture <name>` and look at the file.
3. Import it in the page, give it meaningful `alt` text and a caption.

## Files

- `fixtures.ts`, `seed.ts` build Example through the app's own temple and ritual
  services, with fixed operation IDs (a rerun finds the temple by slug, rituals by
  receipt).
- `browser.mts` is a small Chrome DevTools Protocol client (Node's global
  WebSocket), so there is no Playwright dependency.
- `capture.mts` is the list of shots.

The seed writes to the local development database, so only run it against
`magickli_dev`, as the other `local-development` tasks require.
